Anatomy of a $10k AWS Bill: NAT Gateway Bytes, S3-to-Lambda Loops & the 15-Minute CloudTrail Checklist

Almost every viral "I woke up to a $14,000 AWS bill" postmortem traces back to one of three architectural oversights that default tutorials skip. None of them require high user traffic—all three can drain a startup's bank account overnight while you sleep.

1. The Silent NAT Gateway → S3 Data Bleed

When EC2 instances, ECS tasks, or VPC-attached Lambda functions inside a private subnet read or write Amazon S3 or DynamoDB, AWS routes that traffic through your NAT Gateway by default unless you configure a VPC Endpoint.

In US East/West and EU West, AWS charges $0.045 per GB processed through a NAT Gateway on top of the hourly fee. Moving 50 TB/month of backups, logs, or media to S3 costs ~$2,304/month in avoidable data-processing fees—even though S3 sits inside AWS's own network.

The $0 Terraform Fix: VPC Gateway Endpoints

AWS provides VPC Gateway Endpoints completely free ($0/hr, $0/GB) for exactly two services: S3 and DynamoDB.

resource "aws_vpc_endpoint" "s3_gateway" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.${var.aws_region}.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = aws_route_table.private[*].id
}

2. The Overnight S3 → Lambda Recursion Loop (And the Hidden S3 API Bill)

Classic serverless failure: an S3 ObjectCreated trigger invokes a Lambda function (e.g., resizing an image or compressing logs), and the function writes its output back into the same S3 bucket without non-overlapping prefix filters.

Because new AWS accounts default to 1,000 concurrent Lambda executions, a single unthrottled loop running at 500 concurrency for 8 hours overnight triggers ~36 million invocations—and the nastiest part of the bill isn't even Lambda compute: S3 PUT + GET API charges ($0.0054 per 1,000 requests) silently add hundreds to thousands of dollars on top.

Hardening Rule + Emergency CLI Brake

  • Always write processed artifacts to a separate destination bucket (or enforce strict non-overlapping prefixes).
  • Set reserved_concurrent_executions (e.g., 25) on every event-driven Lambda.
  • If a loop is already firing live, block all new invocations immediately with one CLI command:
aws lambda put-function-concurrency \
  --function-name asset-processor \
  --reserved-concurrent-executions 0

3. Leaked IAM Keys & Multi-Region GPU Cryptojacking

When a long-lived IAM Access Key leaks (or is stolen via EC2 IMDSv1 SSRF), attackers rarely launch servers in us-east-1. They spin up p4d.24xlarge and g5 GPU instances across 15 unused regions like ap-southeast-2 or eu-north-1 where founders never check.

Attach an IAM Permissions Boundary (or Organization SCP) using aws:RequestedRegion with NotAction excluding global services (iam:*, sts:*, route53:*, cloudfront:*, budgets:*, ce:*) so you never lock yourself out while blocking unauthorized regions and GPU families.

4. The 15-Minute CloudTrail Containment Checklist (Don't Delete First!)

When a spike hits, the worst mistake founders make is immediately running aws iam delete-user. Deleting the compromised principal before exporting forensic logs makes it harder to present a clean timeline in an AWS Support Billing Credit Appeal.

  1. Minutes 0–5 (Freeze, Don't Delete): Run aws iam update-access-key --status Inactive and attach an explicit Deny * inline policy to lock out the attacker while preserving audit history.
  2. Minutes 5–10 (Preserve CloudTrail): Export recent activity via aws cloudtrail lookup-events --max-results 50 > incident_trail.json and snapshot Cost Explorer by SERVICE and REGION.
  3. Minutes 10–15 (All-Region Sweep & Guardrails): Loop across all enabled regions to terminate rogue EC2/NAT/Bedrock resources, enable Root MFA + AWS Budgets + Cost Anomaly Detection, and then submit your structured AWS Support Billing case (noting that goodwill credits remain at AWS's discretion).
